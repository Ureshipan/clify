# Архитектура CLIFY

CLIFY пока состоит из общего сетевого Rust-ядра и настольной оболочки. Android-приложение и мобильный аудиодвижок не реализованы.

## Слои

- `src/lib.rs` — клиент Subsonic: авторизация, медиатека, плейлисты, очередь, оценки и scrobbling. Пароли и токены не записываются в файлы приложения.
- `src/audiomuse.rs` — отдельный клиент AudioMuse-AI: сессия или токен, подборки по треку, настроению и исполнителю.
- `src/cache.rs` — кэш по паре сервер/пользователь, атомарная запись, совместная блокировка загрузок в пределах процесса и вытеснение аудио по времени доступа. `CachedAudio` удерживает файл, пока он используется плеером или предзагрузкой. Лимит временно может быть превышен закреплёнными файлами; обложки и метаданные в аудиолимит не входят.
- `src/prefetch.rs` — один фоновый работник, который готовит максимум два следующих уникальных трека. Предзагрузка и пользовательский запрос одного трека разделяют загрузку. При смене очереди устаревшая работа отменяется кооперативно; блокирующий сетевой вызов должен сначала завершиться или достичь тайм-аута.
- `src/queue.rs`, `src/lyrics.rs`, `src/sleep_timer.rs` — независимые от UI операции очереди, временные метки текстов и таймер сна.
- `src/main.rs`, `src/ui.rs` — состояние приложения и графические экраны egui. Сеть и подготовка аудио запускаются вне потока интерфейса; сообщения от устаревшего воспроизведения или сессии игнорируются.
- `src/player.rs`, `src/mpris.rs` — настольный процесс mpv с JSON IPC, резервный ffplay и Linux MPRIS. Это временный настольный аудиобэкенд; для Android потребуется отдельная интеграция.

## Кэш и сеть

Аудиофайл сначала записывается во временный файл и синхронизируется с диском; готовое имя появляется только после успешной записи. Неполные HTTP-ответы не используются как полные треки. При временных ошибках соединения или HTTP 5xx выполняются ограниченные повторные попытки; ошибки авторизации не повторяются автоматически. Оставшиеся после сбоя старые временные файлы очищаются при настройке лимита.

Метаданные кэшируются на пять минут; изменения на сервере через CLIFY инвалидируют их. Старый ответ, пришедший после изменения, не может перезаписать новый кэш. При недоступности сервера допускается использование устаревшего кэша, но ошибки авторизации и ошибки API не скрываются. Несколько экземпляров приложения пока не разделяют блокировки между процессами.

Первое воспроизведение ждёт полной загрузки трека. Кэш не является полноценным автономным режимом: при новом запуске вход проверяется на сервере. Кэшированные файлы не являются закреплёнными офлайн-загрузками и могут быть вытеснены.

## Очередь и тексты

Сохранение и восстановление очереди на сервере запускается пользователем вручную: стандартный `savePlayQueue` меняет общую сохранённую очередь аккаунта. Стандарт хранит текущий трек по ID, поэтому при нескольких вхождениях одного ID восстановится первое. Позиция восстанавливается через mpv, а ffplay запускает трек с начала. ReplayGain передаётся в mpv при запуске следующего трека и зависит от тегов в файле.

Тексты читаются через OpenSubsonic `getLyricsBySongId`. Для построчно синхронизированного текста учитывается `offset`; переход по строке требует mpv. Источник текста — только подключённый сервер.

## Проверки

Тесты запускают локальные HTTP-серверы и не требуют реального Navidrome. MPRIS отдельно проверяется через временную D-Bus-сессию. Настоящее воспроизведение, интерфейс, Windows, Android и совместимость с конкретными версиями серверов требуют дополнительных интеграционных проверок.

Протоколы: [Navidrome Subsonic API](https://www.navidrome.org/docs/developers/subsonic-api/), [OpenSubsonic lyrics](https://opensubsonic.netlify.app/docs/endpoints/getlyricsbysongid/), [AudioMuse-AI](https://github.com/NeptuneHub/AudioMuse-AI/blob/main/docs/ALGORITHM.md).
